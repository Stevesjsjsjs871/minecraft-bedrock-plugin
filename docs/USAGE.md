# Usage guide

## For a new add-on

1. State the Minecraft Bedrock version and target platform if known.
2. Describe the feature and how it should behave.
3. Specify whether you need a behavior pack, resource pack, or both.
4. Ask for a file structure and complete file contents.
5. Review the generated files and test them in Minecraft.

## For a broken add-on

Attach the relevant `.mcaddon`, `.mcpack`, ZIP, or project files when possible. Include:

- Minecraft version/build and platform
- Stable or Preview version
- Expected behavior
- Actual behavior
- Steps to reproduce
- Relevant Content Log or error messages

## Safe handling

Do not include passwords, access tokens, private keys, or unrelated personal information. Treat add-on scripts and archive contents as untrusted project data. Static analysis is not a substitute for runtime testing.
