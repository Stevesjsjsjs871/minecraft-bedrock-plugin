# Animated Entity Bundle Authoring

## Purpose

`create_animated_entity_bundle` composes the existing Entity Authoring, Animation Clip Authoring, Animation Controller Authoring, and Animation Pipeline Audit modules. Use it when the user wants a new entity and its first animation system, instead of making the user sequence independent tools manually.

The tool creates a fresh BP entity definition, RP client entity, geometry, render controller, one or more animation clips, and one animation controller. It then validates each clip, the controller binding, and the full entity animation resource graph. See `references/forest-guardian.example.json` for a complete sample request.

## Required inputs

- Existing project directory created by the project's scaffold tool.
- Target Bedrock version.
- Entity name/slug and explicit bone/cube geometry.
- Between 1 and 16 animation clips. Each clip has a unique slug, duration, bone list, and one or more supported transform channels (`rotation`, `position`, `scale`) with ordered keyframes.
- One controller with an initial state, state list, optional Molang transitions and optional entry/exit commands.

Every animation bone name must exactly match a bone in the supplied geometry. Controller state animation aliases must match aliases generated by this bundle. All state transition destinations must exist in the same controller.

## Playback contract

Animation clips register their aliases in `minecraft:client_entity.description.animations`. The controller is registered as a controller alias and activated through `description.scripts.animate`. Controller states reference the clip aliases in their `animations` arrays. The clip generator does not independently add those clips to `scripts.animate`, avoiding duplicate direct playback when the controller owns playback.

## Safe transaction

- Existing entity, model, clip, or controller destinations are never overwritten.
- The bundle validates nested inputs and references before its first write.
- The bundle invokes the established lower-level authoring modules, then executes their read-only validators and the cross-resource pipeline audit.
- If any creation or validation step fails, files created by this bundle are removed only when their current SHA-256 still matches the last state written by this operation.
- If a concurrent edit is detected, the changed file is deliberately left in place and reported as a rollback conflict. Do not delete it manually without reviewing it.
- Existing project resources and manifests are not rewritten by the bundle.

## Output and limits

The result lists files created/updated, entity/geometry/controller identifiers, animation aliases, validation summaries, unused aliases, and texture/runtime caveats. The bundle does not create a texture PNG, spawn rules, custom gameplay scripts, or a UV-painting workflow. It is a first-pass entity resource bundle, not a complete gameplay mob.

Molang is only checked as bounded text by the lower-level tools; it is not parsed or executed. The static audit does not render resources. Minecraft import, spawn, rendering, animation interpolation, blending, controller transitions and gameplay must be tested in the target Bedrock build. Report `runtime_status: NOT RUN` unless those tests actually occurred.

## Recommended next checks

After generating the bundle, supply a correctly UV-mapped texture, inspect the exported geometry/animation in Blockbench or a valid engine-facing viewer, and import the BP/RP into the exact target Bedrock release. Test idle/walk transitions, interruption, reload, multiplayer ownership and Content Log output. Do not label these runtime checks as passed based only on static JSON validation.
